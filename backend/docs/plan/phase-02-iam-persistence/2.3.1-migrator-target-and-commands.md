# 2.3.1 Validación del destino y de los comandos del migrator
- status: baseline
- layer: infrastructure
- depends: 2.2.1
- files:
  - app/core/migrations.py  # allowlisted target, safe commands, advisory lock, JSON events
  - scripts/migrate.py      # thin CLI entry point
- acceptance:
  - AC1 | solo se aceptan upgrade head, current y check | tests/unit/test_migrations.py::test_parse_command_accepts_only_safe_commands
  - AC2 | se rechazan revisiones arbitrarias | tests/unit/test_migrations.py::test_parse_command_rejects_arbitrary_revisions
  - AC3 | se rechaza un destino fuera del host, la base de datos o el usuario permitidos | tests/unit/test_migrations.py::test_target_rejects_unapproved_configuration
  - AC4 | un destino inválido termina con un JSON controlado antes de crear un engine | tests/unit/test_migrations.py::test_invalid_target_exits_with_controlled_json_without_creating_an_engine
  - AC5 | la CLI nunca muestra el secreto de la base de datos | tests/unit/test_migrations.py::test_cli_does_not_emit_the_database_secret

## Description
`scripts/migrate.py` delega en `app.core.migrations.main`, que valida el destino
contra listas de permitidos antes de abrir ninguna conexión, toma un advisory lock y
solo ejecuta `upgrade head`, `current` o `check`.
Documentado en `../docs/backend/alembic/BACK-DB-MIGRATIONS-BASELINE.md`.
