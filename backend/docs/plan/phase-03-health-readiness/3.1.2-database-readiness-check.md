## Description
`_probe_database` ejecuta `SELECT 1`, lee `public.alembic_version` y la compara con
la única head empaquetada en `alembic.ini`; si la conexión falla, hay varias heads o
la revisión no coincide, lanza un error que `check_database` convierte en `failed`.
`get_readiness_status` agrega las dependencias en `ready` / `not_ready`.
Ningún test existente cubre el caso "revisión distinta de la head → failed" (los
tests unitarios sustituyen la sonda y el de base de datos solo cubre el caso en la
head); esa verificación es trabajo nuevo de la subtask 3.1.3. Documentado en `../docs/backend/backend-health-readiness-checks.md`.
